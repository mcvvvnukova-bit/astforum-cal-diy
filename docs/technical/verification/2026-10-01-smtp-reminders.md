## Реальная отправка

1 октября 2026 года в 00:08:05 МСК worker обработал три заранее запланированных тестовых задания. В 00:08:06 сервер Gmail принял все три письма с SMTP 250. Отправитель: `АСТ Форум <notifications@astforum.ru>`; получатель был явно согласован пользователем и скрыт в публичном отчёте.

| Напоминание | Тестовая запись | Результат задания | Попытки |
|---|---:|---|---:|
| За 24 часа | 11 | `smtp_accepted` | 1 |
| За 60 минут | 12 | `smtp_accepted` | 1 |
| За 15 минут | 13 | `smtp_accepted` | 1 |

Журнал Stalwart содержит ровно три отправки на согласованный адрес и события `delivery.delivered` / `delivery.completed` для очередей `332445746754262016`, `332445746836051456`, `332445746861217792`. SMTP-сервер получателя: `gmail-smtp-in.l.google.com`; транспорт: TLS 1.3.

INFO-журнал Stalwart не выводит Message-ID. Поэтому ожидаемые Message-ID из заданий и доставленные очереди зафиксированы отдельно; соответствие подтверждено количеством, получателем и окном принятия тестовых отправок. По отдельному Message-ID конкретная очередь не заявляется. Размещение писем во «Входящих» или «Спаме» не проверено.

## Проверки и найденные исправления

- 52 обычных теста прошли; дополнительный тест PostgreSQL прошёл отдельно на временной БД. Целевая проверка типов с ES5, Biome, Compose, синтаксис worker и Git whitespace прошли.
- Полная производственная сборка приложения и проверка типов Next.js прошли для образа `e62aef0`. Финальный образ добавляет проверенную конфигурацию Turbo; исполняемый код приложения тот же.
- Реальный PostgreSQL выявил гонку `upsert` с `P2002`. Исправление учитывает только подтверждённый дубль с тем же ключом. 20 конкурентных сверок создали одно задание; 30 обработчиков отправили одно письмо в локальный SMTP-приёмник. Повтор и отмена не создали дополнительных сообщений.
- Сборка выявила несовместимость spread по `Set` с ES5. Использован эквивалентный `Array.from`.
- Первый запуск выявил фильтрацию новой переменной через Turbo. Добавлена `BOOKING_REMINDER_EVENT_TYPE_IDS` в `globalEnv`; тест настоящего дочернего процесса воспроизвёл отсутствие значения и прошёл после исправления.
- Пять параллельных авторизованных вызовов рабочего POST cron прошли. Без секрета и с неверным секретом получен HTTP 401, включая публичный endpoint.
- Отмена и перенос до срока дали `skipped` с нулём попыток. Для пропущенного срока задание не создано. Последующие вызовы cron не повторили три успешные отправки.
- Все 12 тестовых записей отменены. Будущие тестовые задания сняты; историю терминальных заданий сохранили. Три исходные записи и 19 соседних контейнеров сохранили состояние и идентичность.
- Публичные страницы входа, записи на демо, основного сайта, dev landing и Outline отвечают HTTP 200. Календарь демо проверен во встроенном браузере Codex после развёртывания.

## Конфигурация и откат

Активная конфигурация находится в `/opt/astforum-cal-diy/releases/8b6088261b096d94d0304512b2df4ea32d4cb8ed/`: checkout `source`, override `web-command.override.yaml`, параметры образа `active-image.json` и закрытый отчёт `verification.json`.

Резервная копия: `/opt/astforum-cal-diy/backups/smtp-reminders-20260930T204302Z/`. Сохранены серверное окружение, прежний Compose/override, снимки состояния и дамп БД; оглавление дампа проверено. Секреты не попали в GitHub. Схема БД не менялась.

Чтобы откатить приложение, на VPS с правами администратора сначала остановить worker, восстановить прежнее окружение и пересоздать только web:

```sh
docker compose --env-file /opt/astforum-cal-diy/.env -f /opt/astforum-cal-diy/releases/8b6088261b096d94d0304512b2df4ea32d4cb8ed/source/deployment/astforum/compose.yaml -f /opt/astforum-cal-diy/releases/8b6088261b096d94d0304512b2df4ea32d4cb8ed/web-command.override.yaml --profile reminders stop reminder-worker
install -m 600 /opt/astforum-cal-diy/backups/smtp-reminders-20260930T204302Z/environment.before /opt/astforum-cal-diy/.env
docker compose --env-file /opt/astforum-cal-diy/.env -f /opt/astforum-cal-diy/source/deployment/astforum/compose.yaml -f /opt/astforum-cal-diy/releases/91c17f5baad61d7f729a37dc437f00eb54628401/web-command.override.yaml up -d --no-deps web
```

После отката проверить здоровье web и публичные страницы. Дамп БД для отката приложения восстанавливать не требуется; принятые SMTP письма отозвать нельзя.
